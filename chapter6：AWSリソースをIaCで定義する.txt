## はじめに

これまでにLambda関数をローカル環境で開発・テストできるように整えてきました。
本章では、**AWS CDK（Cloud Development Kit）** を使って、実際のAWS環境に必要なリソースを定義・デプロイします。

AWS CDKを使うことで、Lambda関数、SQS、S3バケットなどのインフラを**コードで管理**し、
環境の一貫性を保ちながら、バージョン管理やレビューが可能になります。


## CDKを使う理由

従来のAWSリソース管理では以下のような問題がありました：

* **GUIでの手動作成**：再現性が低く、設定ミスが発生しやすい
* **CloudFormationのYAML/JSON**：記述が冗長で、管理が煩雑
* **環境間の差異**：開発・本番環境で微妙に異なる設定になりがち

**AWS CDK**では、これらの問題を以下のように解決します：

* **プログラムコードでインフラ定義**：Pythonで記述でき、再利用性が高い
* **型安全性**：IDEの補完機能やエラーチェックが利用可能
* **高水準の抽象化**：ベストプラクティスが組み込まれたコンストラクト
* **CloudFormationへの自動変換**：内部的にCloudFormationテンプレートを生成

### メインスタックの実装

#### 📄 lambda-etl/cdk/stacks/lambda_etl_stack.py

```python
from aws_cdk import (
    Duration,
    Stack,
    aws_lambda as _lambda,
    aws_sqs as sqs,
    aws_s3 as s3,
    aws_lambda_event_sources as lambda_event_sources,
    aws_iam as iam,
    RemovalPolicy,
    CfnOutput,
)
from constructs import Construct
import os


class LambdaEtlStack(Stack):
    def __init__(self, scope: Construct, construct_id: str, **kwargs) -> None:
        super().__init__(scope, construct_id, **kwargs)

        # S3バケットの作成
        etl_bucket = s3.Bucket(
            self,
            "EtlBucket",
            bucket_name=f"lambda-etl-bucket-{self.account}-{self.region}",
            removal_policy=RemovalPolicy.DESTROY,  # 開発環境用（本番では要注意）
            auto_delete_objects=True,  # 開発環境用（本番では要注意）
            versioned=False,
            public_read_access=False,
            block_public_access=s3.BlockPublicAccess.BLOCK_ALL,
        )

        # SQSキューの作成
        etl_queue = sqs.Queue(
            self,
            "EtlQueue",
            queue_name="lambda-etl-queue",
            visibility_timeout=Duration.minutes(5),  # Lambdaのタイムアウトより長く設定
            retention_period=Duration.days(14),
            dead_letter_queue=sqs.DeadLetterQueue(
                max_receive_count=3,
                queue=sqs.Queue(
                    self,
                    "EtlDlq",
                    queue_name="lambda-etl-dlq",
                )
            )
        )

        # Lambda関数の作成
        etl_function = _lambda.Function(
            self,
            "EtlFunction",
            function_name="lambda-etl-processor",
            runtime=_lambda.Runtime.PYTHON_3_12,
            handler="main.lambda_handler",
            code=_lambda.Code.from_asset(
                path="../app",
                exclude=["tests", "__pycache__", "*.pyc"]
            ),
            timeout=Duration.minutes(3),
            memory_size=256,
            environment={
                "S3_BUCKET_NAME": etl_bucket.bucket_name,
                "KEY_PREFIX": "etl-output",
                "PYTHONPATH": "/var/runtime:/var/task",
            },
            retry_attempts=0,  # SQSで再試行を管理
        )

        # Lambda関数にS3への書き込み権限を付与
        etl_bucket.grant_write(etl_function)

        # Lambda関数にSQSからのメッセージ読み取り権限を付与
        etl_queue.grant_consume_messages(etl_function)

        # SQSをLambdaのイベントソースとして設定
        etl_function.add_event_source(
            lambda_event_sources.SqsEventSource(
                etl_queue,
                batch_size=1,  # 一度に1メッセージずつ処理
                max_batching_window=Duration.seconds(5),
                report_batch_item_failures=True,
            )
        )

        # 出力：他のスタックや手動テストで使用するため
        CfnOutput(
            self,
            "BucketName",
            value=etl_bucket.bucket_name,
            description="S3バケット名"
        )

        CfnOutput(
            self,
            "QueueUrl",
            value=etl_queue.queue_url,
            description="SQSキューURL"
        )

        CfnOutput(
            self,
            "QueueName",
            value=etl_queue.queue_name,
            description="SQSキュー名"
        )

        CfnOutput(
            self,
            "FunctionName",
            value=etl_function.function_name,
            description="Lambda関数名"
        )
```

## トラブルシューティング

### よくあるエラーと対処法

#### 1. 権限エラー

```bash
# エラー例
AccessDenied: User is not authorized to perform: sts:AssumeRole

# 対処法：IAMユーザーに適切な権限を付与
# 最低限必要な権限：
# - CloudFormationFullAccess
# - IAMFullAccess
# - S3FullAccess
# - SQSFullAccess
# - LambdaFullAccess
```

#### 2. リソース名の重複

```bash
# エラー例
BucketAlreadyExists: The requested bucket name is not available

# 対処法：バケット名にランダムな文字列を追加
# lambda_etl_stack.py内のbucket_nameを変更
```

#### 3. Python依存関係のエラー

```bash
# エラー例
ModuleNotFoundError: No module named 'pydantic'

# 対処法：Lambda Layerを使用するか、依存関係をパッケージに含める
# 簡易的な解決策として、requirements.txtをappディレクトリに配置
```

## リソースの削除

開発環境のリソースを削除する場合：

```bash
# スタック全体の削除
cdk destroy

# 確認プロンプトで 'y' を入力
```

**注意**: S3バケットにファイルが残っている場合、削除に失敗することがあります。
事前にバケットを空にしてから削除してください。

## 補足：本番環境での考慮事項

本章では開発・学習目的の設定を使用していますが、本番環境では以下の点を検討してください：

* **S3バケット**: `RemovalPolicy.RETAIN`に変更
* **暗号化**: S3とSQSでKMS暗号化を有効化
* **監視**: CloudWatchアラームの設定
* **ネットワーク**: VPC内でのプライベート通信
* **権限**: 最小権限の原則に基づいたIAMロール設計
