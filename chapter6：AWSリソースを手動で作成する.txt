## はじめに

これまでにLambda関数をローカル環境で開発・テストできるように整えてきました。
本章では、**AWSコンソール**を使って実際のAWS環境に必要なリソースを作成し、Lambda関数をデプロイします。

手動でリソースを作成することで、各サービスの設定項目や関係性を理解しながら、
**最短時間で動作する環境**を構築できます。


## 作成するリソース

今回作成するAWSリソースは以下の3つです。

| 作成順序 | リソース | 目的 |
|---------|------|----------|
| 1 | **S3バケット** | CSVファイルの保存先 |
| 2 | **SQSキュー** | JSONメッセージの受信 |
| 3 | **Lambda関数** | ETL処理の実行 |


## ステップ1：S3バケットの作成

### 1-1. S3コンソールでバケットを作成

1. **AWSコンソール**にログインし、**S3**サービスを開く
2. 「**バケットを作成**」をクリック

![](https://storage.googleapis.com/zenn-user-upload/d1e0a8396e9e-20250923.jpeg)

3. 以下の設定を入力する

**基本設定**
- **バケットタイプ**: **汎用**を選択
- **バケット名**: `lambda-etl-bucket-[あなたの名前]-[日付]`
  - 例：`lambda-etl-bucket-fd2025-20250924`
  - バケット名は全世界でユニークである必要があります
- **AWSリージョン**: `アジアパシフィック（東京）ap-northeast-1`

**オブジェクト所有権**
- **ACL無効（推奨）** を選択

![](https://storage.googleapis.com/zenn-user-upload/ca1334930ce7-20250923.jpg)


**パブリックアクセス設定**
- **パブリックアクセスをすべてブロック**にチェック（デフォルト）

**バケットのバージョニング**
- **無効**を選択

![](https://storage.googleapis.com/zenn-user-upload/7836f0cbc407-20250923.jpeg)

**デフォルト暗号化**
- **デフォルト設定**のまま

4. 「**バケットを作成**」をクリック

![](https://storage.googleapis.com/zenn-user-upload/fc417525cae3-20250923.jpeg)

### 1-2. 作成確認

バケット一覧に作成したバケットが表示されることを確認してください。

![](https://storage.googleapis.com/zenn-user-upload/9451757a148e-20250923.jpeg)

### 3-2. 関数コードのデプロイ

#### デプロイパッケージの作成

ローカルで以下のコマンドを実行し、デプロイ用のzipファイルを作成します。

```bash
chmod +x deploy.sh
./deploy.sh
```

**📄 lambda-etl/deploy.sh**

```bash
#!/bin/bash

# Lambda関数デプロイパッケージ作成スクリプト

set -e

echo "=== Lambda デプロイパッケージ作成開始 ==="

# プロジェクトルートディレクトリで実行されているか確認
if [ ! -d "app" ]; then
    echo "エラー: appディレクトリが見つかりません"
    echo "プロジェクトルートで実行してください"
    exit 1
fi

# 既存のデプロイパッケージを削除
echo "既存のデプロイパッケージをクリーンアップ..."
rm -rf deploy-package
rm -f lambda-etl-function.zip

# デプロイ用ディレクトリを作成
echo "デプロイ用ディレクトリを作成..."
mkdir deploy-package

# appディレクトリをコピー（不要なファイルを除外）
echo "アプリケーションコードをコピー..."
rsync -av \
  --exclude='__pycache__' \
  --exclude='*.pyc' \
  --exclude='*.pyo' \
  --exclude='.pytest_cache' \
  --exclude='.coverage' \
  --exclude='htmlcov' \
  --exclude='*.log' \
  --exclude='.DS_Store' \
  app deploy-package/

# zipファイルを作成
echo "zipファイルを作成..."
cd deploy-package
zip -r ../lambda-etl-function.zip . -x "*.pyc" -x "*__pycache__*"
cd ..

# パッケージサイズを表示
PACKAGE_SIZE=$(du -h lambda-etl-function.zip | cut -f1)
echo ""
echo "=== デプロイパッケージ作成完了 ==="
echo "ファイル: lambda-etl-function.zip"
echo "サイズ: $PACKAGE_SIZE"
echo ""
echo "次のステップ:"
echo "1. AWS Lambda コンソールでlambda-etl-function.zipをアップロード"
echo "2. ハンドラーが 'app.main.lambda_handler' になっていることを確認"
echo ""

# パッケージ内容を確認（オプション）
read -p "パッケージ内容を確認しますか? (y/N): " confirm
if [[ $confirm == [yY] ]]; then
    echo ""
    echo "=== パッケージ内容 ==="
    unzip -l lambda-etl-function.zip
fi
```


**スクリプトの作成と実行**

1. プロジェクトルートに`deploy.sh`を作成し、上記の内容を保存
2. 実行権限を付与：
```bash

```

3. デプロイパッケージを作成：
```bash
./deploy.sh
```

5. 以下のポリシーを検索して追加する

![](https://storage.googleapis.com/zenn-user-upload/91cd58a9a875-20251002.jpg)

## トラブルシューティング

### よくあるエラーと対処法

**1. バケット名が重複**
```
BucketAlreadyExists: The requested bucket name is not available
```
対処：バケット名に追加の識別子（日付、名前など）を付けて再作成

**2. 権限エラー**
```
AccessDenied
```
対処：IAMロールにS3FullAccess、SQSFullAccessが正しく付与されているか確認

**3. Lambda関数のインポートエラー**
```
Unable to import module 'main'
```
対処：zipファイルの構造を確認。main.pyがルートディレクトリにあることを確認

## リソースの削除

学習完了後、料金を避けるためリソースを削除する場合：

1. **Lambda関数**：削除
2. **SQSキュー**：両方削除（メインキュー、DLQ）
3. **S3バケット**：オブジェクトを削除してからバケット削除
4. **IAMロール**：Lambda関数削除時に自動削除される
